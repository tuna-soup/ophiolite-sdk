# Ophiolite SDK guidance

This repository owns the supported 0.x public client over preview contracts.
Use the six packaged guides under `ophiolite/skills/`; `ophiolite skills path`
locates them after installation. A guide explains an authorized workflow; it does
not grant new permission to publish, share, send messages or inspect credentials.
Authorization already given in the user's task persists; do not ask repeatedly.

Preserve scientific identity, exact revisions, source authority, units, axes,
missingness and provenance. Never resample, convert, infer identity or broaden
access silently. Local Python runs locally; recording a run does not launch a job.
Reading needs no binding or run. Report unavailable data and refusals honestly.

Use `ophiolite.auth` for credential ownership. Never copy token values into logs,
notebooks, prompts, source or browser storage. Keep credentials and work folders
private. Recover publication using the original folder; read grants first after
an uncertain sharing response. Never retry sharing automatically.

Generated contracts come from the audited pinned snapshot. Regenerate models and
TypeScript operations with their tools; do not hand-edit generated declarations.
New copied inputs require explicit provenance and public-input checks. Preserve
unrelated work. Use explicit staging, named tests and accurate evidence. Template
fixtures prove bounded examples, not customer connectors or live identity systems.

Python and TypeScript versions stay aligned. A schema/profile version change
requires explicit compatibility work; a new required field or scientific meaning
is not an additive change. See CHANGELOG.md and README.md for the 0.x transition
policy, retired kit modules, supported scope and remaining release gates.
